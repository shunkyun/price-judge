# 価格チェッカー（price-judge）v1.1

服・靴・家電などの価格が **安い / 適正 / 高い** かを、信頼できる通販サイトから**今回実際に取得した価格だけ**で判定するWebアプリです。

- 最初の画面は入力欄1つ（商品名 または 商品ページURL）＋写真ボタン＋「調べる」だけ
- 入力中に予測候補を表示（固定の商品辞書のみ。他の利用者の入力は候補に出ません）
- 商品名が分からないときは写真から AI が商品名を推定 → ユーザーが候補を選んで確定
- 結果はダッシュボード：判定・根拠・サンプル数・価格推移グラフ・価格分布・出典一覧（URL・取得日時つき）
- **AIは価格も説明文も作りません。** 数値はすべて取得データからプログラムで計算し、説明文は定型文です

> 非エンジニア向けの使い方・公開手順は [docs/使い方ガイド.md](docs/使い方ガイド.md) を参照してください。
> 修正履歴は `reviews/` を参照。

## 1. 起動方法

### A. いちばん簡単（デモモード・APIキー不要）
- Mac / Linux：`./scripts/start.sh` → http://localhost:8000
- Windows：`scripts\start.bat` をダブルクリック（Python 3.12 以上が必要）

APIキーが無いと自動で **デモモード** になり、画面上部に「架空のサンプルデータ」と常時表示されます。
デモで検索できる商品：ナイキ エアフォース1 '07 / ユニクロ ウルトラライトダウンジャケット / ソニー WH-1000XM5 / Apple AirPods Pro 第2世代 / アディダス サンバ OG / 無印良品 スニーカー（＝件数不足の例）

ローカル起動は既定で自分のPCからのみ接続可能（`127.0.0.1`）。LANに出す場合だけ `HOST=0.0.0.0`。

### B. Docker
```sh
cp .env.example .env        # 必要なキーを記入
docker compose up --build   # → http://localhost:8000
```

### C. 公開して他の人に見せる
| 方法 | 手順 | 備考 |
|---|---|---|
| **Render（推奨）** | GitHubにpush → Render で「New > Blueprint」→ `render.yaml` を選択 → 環境変数を入力 | ディスク付きで価格推移が蓄積される。`TRUSTED_PROXY_HEADER=CF-Connecting-IP` 設定済み。**永続ディスクは有料プラン**。無料プランは Blueprint Path に `render.free.yaml` を指定（ディスクなし。推移が保存されないだけで判定は動く）。キーは Render の Environment 画面にのみ入力 |
| Docker 対応の任意のホスト | `Dockerfile` をそのまま使用。`PORT` 環境変数に対応 | 推移を残すなら `/data` を永続ボリュームに。プロキシ配下なら `TRUST_PROXY`（下表）。**Cloudflare を通らない環境では `TRUSTED_PROXY_HEADER` を設定しない**（利用者が偽装できる）。必要なら `TRUSTED_PROXY_CIDRS` でプロキシの範囲を限定。コンテナは root で起動し、`/data` の所有者を直してから非 root（appuser）に切り替える |
| Vercel | リポジトリを Import（`vercel.json` / `api/index.py` 同梱） | **DBが永続化されない**（推移は蓄積されない）。1リクエスト4.5MB上限のため4.5MB超の画像は失敗。レート制限はインスタンスごと。デモ公開向け |

### D. 配布用 zip
```sh
./scripts/package.sh        # → dist/price-judge.zip（.env* ・DB・reviews/ は含まれない。Windows は scripts\package.bat）
```

### テスト
```sh
python3 -m pip install -r requirements-dev.txt
python3 -m pytest -q
```

## 2. 環境変数（`.env.example` 参照）

| 変数 | 必須 | 内容 |
|---|---|---|
| `RAKUTEN_APP_ID` / `RAKUTEN_ACCESS_KEY` | 推奨 | 楽天ウェブサービスのアプリID（UUID形式）とアクセスキー（`pk_...`）。2026年の刷新以降は**両方必須**。`RAKUTEN_ORIGIN` はアプリ登録URLと一致させる必要がある場合に設定 |
| `YAHOO_APP_ID` | 推奨 | Yahoo!デベロッパーネットワークの Client ID（商品検索API v3） |
| `KEEPA_API_KEY` | 任意・有料 | Amazon.co.jp の価格履歴（Amazon商品URL指定時）。Amazon 公式の PA-API 5.0 は廃止され Creators API に移行済みで、**Amazonアソシエイト登録と直近30日で10件以上の適格売上が必要**なため未対応 |
| `SHOP_SEARCH_MAX` | | 検索語の種類（家電・服・靴など）に合う専門店の**楽天市場店・Yahoo!店に絞った検索**を、取得元ごとに最大何店追加するか（既定2、0で無効、最大5）。1店につきAPI呼び出し1回（約1秒）増える |
| `LLM_API_KEY` `LLM_BASE_URL` `LLM_MODEL` `LLM_VISION_MODEL` | 任意 | OpenAI互換API。画像からの商品特定に使用。`LLM_NORMALIZE=1` で検索語の不要語削除（削除のみ許可） |
| `LLM_DAILY_LIMIT` | | AI呼び出しの1日上限（既定 100） |
| `DEMO_MODE` | | `auto`（既定：楽天・Yahooのキーが無ければデモ）/ `1` / `0` |
| `MIN_SAMPLES` / `MIN_SOURCES` / `MIN_SELLERS` | | 判定に必要な最低 有効サンプル数(10) / 取得元サイト数(2) / 店舗数(3) |
| `OUTLIER_IQR_K` | | 外れ値判定の係数（既定 1.5） |
| `RELEVANCE_MIN` | | 商品名一致度の下限（既定 0.6） |
| `RECENT_DAYS` | | 取得から何日以内を現在価格とみなすか（既定 30） |
| `RATE_ANALYZE_PER_MIN` / `RATE_IDENTIFY_PER_MIN` / `RATE_SUGGEST_PER_MIN` | | IP単位の1分あたり上限（10 / 3 / 120） |
| `UPSTREAM_INTERVAL_SEC` | | 取得元APIごとの最小呼び出し間隔（既定 1.0秒、直列化） |
| `ACCESS_CODE` | | 設定すると関係者限定公開になり、画面でアクセスコード入力を求める（`/api/status` 以外のAPIに必要） |
| `TRUSTED_PROXY_HEADER` | | 手前のプロキシが必ず上書きする利用者IPヘッダ。**既定なし（ヘッダは一切信用しない）**。Render は `CF-Connecting-IP`（render.yaml で設定済み）。旧名 `CLIENT_IP_HEADER` も読む |
| `TRUSTED_PROXY_CIDRS` | | 設定すると、接続元がこの範囲（カンマ区切り CIDR）のときだけ上記ヘッダ・`X-Forwarded-For` を使う |
| `ACCESS_CODE_IP_MAX_FAILURES` | | アクセスコード誤りの回線（IP）単位の上限／10分（既定50）。端末単位は `ACCESS_CODE_MAX_FAILURES`。**ロック中も、すでに利用券を持つ人は使い続けられる** |
| `MAX_SESSIONS_PER_IP` / `SESSION_HOURS` | | 1回線から1時間に開始できる利用数（既定30）／利用券の有効時間（12） |
| `SESSION_SECRET` | | 利用券の署名鍵（未設定なら起動ごとに自動生成＝再起動で再入力が必要） |
| `ADMIN_TOKEN` | | 画面上部の「管理者向けの注意」を `?admin=<値>` で表示する（自分のPCで開いたときは常に表示） |
| `TRUST_PROXY` | | `X-Forwarded-For` の右から N 段目を利用者IPとする（0=使わない。左端は偽装可能なため使わない） |
| `RATE_IP_AUTHED_PER_MIN` | | アクセスコード認証済みのIP単位上限（共有回線向け・既定60）。端末（利用券）単位は `RATE_ANALYZE_PER_MIN`。**端末単位の上限は目安で、実際の上限は IP あたりこの値**（R3-7） |
| `ACCESS_CODE_MAX_FAILURES` | | アクセスコード誤りの端末単位の上限／10分（既定10） |
| `MAX_QUEUE_WAIT_SEC` / `TREND_MIN_POINT_N` | | 混雑時の待ち上限秒（20）／推移の1日あたり最小件数（3） |
| `HASH_SALT` | | 推移用識別子の秘密値（未設定なら自動生成してDBに保存） |
| `DB_PATH` / `DB_RETENTION_DAYS` | | SQLite のパス（既定 `./data/prices.db`）/ 保存期間（既定 400日） |
| `HOST` / `PORT` | | 待ち受け（ローカル既定 127.0.0.1:8000） |

自動判定（楽天＋Yahoo の2サイト以上）を行うには **楽天とYahooの両方のキー** が必要です（`MIN_SOURCES=2` のため）。

## 3. 価格の定義

| 用語 | 定義 | 使い方 |
|---|---|---|
| **総支払額** | 税込価格 ＋ 送料 ＋ 必須手数料 | **判定は常にこれで行う**。送料・手数料が確定できないものは**判定から除外し、件数にも数えない**（推測しない） |
| 実質価格 | 総支払額 − 付与ポイント | **参考表示のみ**（分布グラフの表示切替）。判定には使わない。ポイントを取得元が示したものだけ |

- 楽天：`postageFlag=0`（送料込み）のみ送料0として確定。送料別は金額がAPIに無いため「送料不明」→除外。検索時に送料込み商品を優先取得。税別表示（`taxFlag=1`）は除外。ポイントはAPIの `pointRate`（倍率）から「税抜価格×倍率%」で計算（**税率10%前提の計算値**。画面に「※倍率からの計算値」と表示）。商品URLのクエリ（`rafcid` 等、アプリIDを含む）は除去
- Yahoo：`shipping.code=2`（送料無料）のみ確定。条件付き送料無料は不明扱い。ポイントは `point.amount`
- URL指定のページ：JSON-LD / OGP の構造化データのみ。**通貨が JPY と明示されていない、税抜、バリエーションで価格が複数、送料の地域差・通貨が不明**のいずれかなら採用しない
- 必須手数料：楽天・Yahoo・公式/量販店の通常購入では購入者手数料が無いため0。不明な取得元（フリマ等）は「手数料不明」として除外
- 比較母集団は「送料が確定できる出品（送料無料・送料込み）」であり、その旨を判定理由に表示

## 4. 判定アルゴリズム（すべて決定的・LLM不使用）

判定に使うのは **今回の検索で取得したデータのみ**。過去に蓄積したデータは推移グラフにだけ使い、件数には加えません。

1. **許可リスト**（`config/sources.json`）外のURLは除外。https・既定ポートのみ。ドメイン完全一致またはサブドメインのみ（`item.rakuten.co.jp.evil.com` 等は不一致）。公式ストアはパスも限定（例 `uniqlo.com/jp/`）
2. 新品 / 中古の別で分ける（タイトルに「中古」「美品」等を含むものは中古扱い）
3. 同一商品かの確認：
   - 付属品語（「ケース」「互換」「箱のみ」等。クエリに無い語）を含むものを除外
   - クエリ中の**型番・数字トークンは完全一致必須**（`15` は `16` や `150` と不一致、`第2世代` と `第1世代` は不一致）
   - タイトルにあってクエリに無い**区別語**（Pro / Max / mini / Plus / Ultra / Lite / SE / キッズ / ジュニア 等）があれば別モデルとして除外
   - 文字の一致度が `RELEVANCE_MIN` 未満は除外
4. `RECENT_DAYS` より古い取得、同一URLの重複（最新のみ）を除外
5. 送料・手数料不明を除外
6. **同一店舗・同一総支払額**の出品（色・サイズ違い）を1件に集約
7. **IQR法**で外れ値除外：Q1−1.5×IQR 未満 / Q3+1.5×IQR 超。フェンスは除外前のデータで1回だけ計算し、判定の「安すぎ／かなり高い」にも同じフェンスを使う
8. 有効サンプル数 < `MIN_SAMPLES`、取得元サイト数 < `MIN_SOURCES`、店舗数 < `MIN_SELLERS` のどれか → **「データ不足のため判定不可」**（中央値・価格帯は表示しない）
9. 判定（総支払額 P）：P < 下限フェンス → 安すぎ（要注意）／ P < Q1 → **安い** ／ Q1 ≤ P ≤ Q3 → **適正** ／ Q3 < P ≤ 上限フェンス → **高い** ／ P > 上限フェンス → かなり高い
10. 信頼度：高（n≥max(30, 3×MIN_SAMPLES)、IQR/中央値≤0.25、最大店舗シェア≤30%）/ 中（n≥2×MIN_SAMPLES、≤0.5、≤30%）/ 低
11. 過去比較：**総支払額で蓄積した系列だけ**から、直近7日を除く日別中央値の中央値を求めて比較。Keepa 等「商品価格のみ」の系列はグラフに点線で参考表示するだけ

パーセンタイルは線形補間（Excel `PERCENTILE.INC` と同じ）。

## 5. ハルシネーション対策
- 画面の価格はすべて「今回取得したAPIレスポンス / ページ構造化データ」の値で、**出典URL・取得日時（JST）**を併記
- 判定理由は決定的なテンプレート文のみ（AIの自由文の説明は廃止）
- LLMの用途は (a) 画像からの商品名推定（ユーザーが確認して選ぶ）(b) 検索語の不要語削除（追加・言い換えは不採用）に限定。出力中の価格らしき文字列は除去
- デモデータは予約ドメイン `demo.invalid`、DB非保存、実データと混在させない、デモ時はURL取得もしない

## 6. 公開時の安全対策
- IP単位のレート制限、取得元APIごとの直列化（約1リクエスト/秒）、AI呼び出しの1日上限
- 画像は本文受信前にサイズ拒否（Content-Length）、マジックバイトで画像形式を確認
- 画像を選ぶ前に「外部AIサービスに送信されます」と表示・確認
- 入力された検索語は保存しない（推移用の識別子は秘密値付き HMAC-SHA256）。予測候補は固定辞書のみ
- CSP 等のセキュリティヘッダ、https 以外のリンクは表示しない
- 利用規約・プライバシーポリシーページ（`/terms`、公開前に運営者情報を記入）

## 8. アーキテクチャ
```
static/            画面（HTML/CSS/JS・外部ライブラリなし、グラフはSVG）、terms.html
app/main.py        FastAPI（/api/suggest /api/identify /api/analyze /api/status /terms /healthz）＋ガード
app/ratelimit.py   IP単位レート制限
app/service.py     取得→判定（今回分のみ）→推移用に保存
app/adapters/      取得元プラグイン（rakuten, yahoo, keepa, page=URL構造化データ, demo）＋取得元ごとの直列化
app/judge.py       選別・集約・外れ値除外・判定（決定的）
app/textnorm.py    正規化・型番/区別語チェック
app/stats.py       統計（中央値・IQR・パーセンタイル等）
app/trend.py       価格推移（系列ごとに総支払額/商品価格の区別）
app/llm.py         LLM（商品特定・検索語の削除整形）＋1日上限
app/db.py          SQLite（推移専用。検索語はハッシュ化）
config/sources.json 信頼サイト許可リスト
```
**拡張（サービス価格など）**：`PriceAdapter` を継承したクラス（`category="service"`）を `app/adapters/` に追加し `@register`、`config/sources.json` に許可ドメインを追加するだけで取り込めます。

## 9. 取得元の対応状況（対応サイト一覧）
画面の「対応サイト一覧」（`/sites`）にも同じ内容を表示しています。表は `config/sources.json` から `python scripts/sources_table.py` で作ります（手で書き換えない）。

- **自動検索**は楽天市場・Yahoo!ショッピングの**公式API**だけで行います。専門店（家電量販店・セレクトショップ・スポーツ店など）は、その店が楽天市場・Yahoo!ショッピングに出している**公式店に絞った検索**（楽天 `shopCode`／Yahoo! `seller_id`）で価格を集め、「ケーズデンキ（楽天市場店）」のように表示します。取得元の数（`MIN_SOURCES`）は楽天・Yahoo!の2つのまま数えます（専門店を別サイトとして水増ししない）。楽天市場店の価格は楽天の規約どおり保存しません
- 検索語の種類は `config/sources.json` の `category_keywords`（決まった単語表）で判定します。種類が分からない検索では専門店の絞り込み検索はしません（全体検索には各店の出品も含まれ、店名で表示されます）
- **URL指定**は、許可リストのサイトの商品ページ1件だけを、`robots.txt` で許可されている場合に限り読みます（リダイレクト先も毎回確認、確認できない場合は読まない）。検索ページの巡回（スクレイピング）はしません
- 専門店の多くは自社サイトにボット対策（Akamai・Cloudflare 等）があり、クラウドのサーバーからは 403 で読めないことを確認しています（表の ×）。その店の価格は楽天市場店・Yahoo!店があれば自動検索で取得できます
- Amazon.co.jp：PA-API 5.0 は廃止され Creators API に移行。利用には Amazonアソシエイト登録と**直近30日で10件以上の適格売上**が必要なため未対応。Keepa（有料・`KEEPA_API_KEY`）を設定した場合のみ、ASIN を含む URL で価格履歴を参考表示します

## 10. 既知の制限
- 自動検索は楽天＋Yahoo に依存。両方のキーが無いと「判定不可」になりやすい
- 送料別の商品は送料金額がAPIに無いため除外 → 送料込み商品が少ない商品はサンプル不足になりやすい
- 楽天ポイントは税率10%前提の計算値（参考表示のみ）
- 同一商品の判定は文字列ベース（型番・区別語チェックあり）。JANコード照合は未実装。色・サイズ違いは同一商品として扱い、同一店舗・同一価格は集約
- レート制限・キャッシュはプロセス内メモリ（複数インスタンスでは個別）
- Vercel ではDBが揮発するため推移は蓄積されない
- 価格推移は使うほど蓄積（初回は当日の1点のみ）
